# Changelog

All notable changes to Smart Parks Protect are recorded here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and versions follow [semantic versioning](https://semver.org/). Servers run tagged releases, never `main`.

## Unreleased

From Tim's first hour with v2.0.0 on the dev server.

### Added

- An unknown identity from a ChirpStack uplink carries the device's name from the platform as its name, so Needs attention shows "SP010462" instead of "none" and a bulk create names the device after it, as it already did for KPN; existing identities get the name on their next uplink or through Sync devices.
- A ChirpStack source whose gRPC address is still the old form's example (`chirpstack.example.org`) gets the address derived from its web address on the next save, instead of failing every API call with a DNS error.
- An Applications dialog per ChirpStack source (decision D132): every application of the tenant with whether it posts to this source, what else its integration holds, Connect and Disconnect per application with a spinner on the row while ChirpStack answers, "Connect the other N" one after the other, and Refresh; it replaces the one-shot preview and can be opened any time from the row or right after the token is shown. Disconnect removes only this source's URL entry and deletes an integration that held nothing else. `GET /data-sources/{id}/applications`, `POST /data-sources/{id}/disconnect-applications`.
- ChirpStack behind a plain reverse proxy (decision D131): the adapter speaks grpc-web, the protocol ChirpStack's own web UI uses on the same paths, when the API address is `https://host`, so any ChirpStack that opens in a browser works for Test connection, the syncs, downlinks and Connect applications without changes on its side; native gRPC stays for `grpcs://` and `grpc://` addresses. The quick setup takes the address as copied from the ChirpStack browser tab and reads the tenant id from it (a tenant API key cannot ask ChirpStack for its tenant); the API address defaults to the web address.

- ChirpStack applications connected from the tenant (phase 17, decisions D125 to D127): a ChirpStack data source with the API channel on has a "Connect applications" action that puts its webhook on the HTTP integration of every application of the tenant, creating one or appending the URL to the existing list, with the token in the URL so headers are never touched; the result names every application with its outcome; Test connection shows how many applications post to the source; a new source offers the action when its token is shown. `POST /data-sources/{id}/connect-applications`; the ChirpStack webhook accepts `?token=`; the source keeps an encrypted copy of its webhook token, refreshed on rotation, and a source from before needs one rotation.
- The Gateways page has a "Show on live map" button that opens the live map with the gateway layer on, and a gateway's dialog shows its location on a small map that opens the live map on that gateway (`?gateways=1`, `?gateway=<id>`).
- A small map on the entity page and the device page (decision D124): a map card without a title shows the newest position with a thin trail of the last positions, fitted to the trail, still so the page scrolls as usual, and the whole map is a link to the live map on the entity or device.

Each assignment starts at the device's first data (a record, its identity first seen, a log file) or now, an entity per device named as the device is optional with a group, records inside the range get the project, and a device assigned elsewhere in that range is skipped with the reason. `POST /devices/bulk-assign`, server admins.

### Fixed

- The Coverage tab no longer says "Only where collars were: a blank area may still have coverage": too much text, and the heard positions come from any tracker, not only collars.
- Heard positions are coloured dots at every zoom (decision D123), the newest ten thousand in view when there are more; the hexagons stay available to API users with `mode=hexagons`.
- The heard-positions layer loads in the all-projects scope over long windows: the coverage query starts from the receptions and scans positions per device, which uses the compressed chunks' index instead of decompressing every chunk of the window (0.5 s instead of 6 s for 90 days); the map cancels the request of a viewport that is gone and settles a little longer after a move, so panning no longer piles up slow requests; the panel shows a load error with a retry instead of "Loading…" for ever, and the Heard positions row folds like the others.
- A tab opened before a deploy no longer goes blank on its first visit to a page it had not loaded yet: the old page chunk is gone after the deploy, and the app now reloads itself once when a chunk fails to load (with a guard against a reload loop during a real outage), instead of leaving a blank page until a manual refresh.
- Opening an event in All projects works: the event detail read accepts the all scope for a server admin (it answered 422 before), and the dialog's links to the map and the trace go to the event's own project.
- The Decoded tab of a traffic row opens at once instead of after seconds: the lookups of the positions, measurements, states and events of a source event are narrowed to the device, since the hypertables have no index on the source event id and compressed chunks are read per device (76 s cold and 6 s warm for the positions alone on the dev server, 45 ms narrowed).
- In the all-projects scope the gateway layer, the Gateways page, Traffic and the connectivity analysis count devices in no project as well, as the map and the devices list already did (decision D120); before, a server admin saw the positions of an unassigned collar there but not the gateways that heard it.
- Gateway receptions of uplinks that arrived while the identity was unknown never got the device when the identity was linked, so the gateway layer and the coverage missed everything from before the device existed. Linking now gives the receptions the device, and migration 0022 repairs the existing rows.
- The project switcher's list can be scrolled with a finger on a phone: the sidebar sheet blocked touch scrolling in the popover outside it, which is now modal with its own scroll allowance.
- Devices in no project (decision D120): in the all scope the device layer and the Devices tab show them under "Not in a project", with their latest position and their track over the positions that belong to no project; the panel names the gap and links to Server admin, Devices; the all-scope devices list filters by project, "Not in a project" included. - The device layer clusters when zoomed out like the entities: a device cluster is white with a green ring and sits a little down and right of an entity cluster over the same ground, so both stay readable; a single device marker sits beside its animal's marker rather than under it. Clicking a device cluster zooms in.
- The layers panel starts with every row folded, each tab has a Fold all or Unfold all button, the Devices tab's "Without an entity" and "Tracking an entity" sections fold too, and Hide all on the Entities tab hides every project's layers in the all scope (it left the per-project Ungrouped layers showing).
- In the layers panel, folding a row folds everything below it (a project's groups, its Ungrouped row and their entities in the all scope; a group's subgroups anywhere); a search still reaches into a folded subtree. In the all scope the Devices tab's project rows fold as well and carry a switch that shows or hides every device of the project, shown as a dash while only some are on.
- A device whose clock runs ahead (decision D119): a collar sent positions dated 2030, its current state stuck there and its last seen went negative. A record whose device time is more than `CLOCK_AHEAD_TOLERANCE_SECONDS` (an hour) ahead of its delivery is now stored invalid, so it stays off the map, the lists, the rules, the exports and the current state; the trace step says how far ahead the clock is, Needs attention has a Clocks ahead tab and counter (`GET /attention/clock-ahead`), the device page warns with the way to the fix, and the bulk curation job's time offset may span twenty years so such records can be shifted to their real times. "clock ahead" replaces a negative age in the lists.
- On a phone, the entity page and the device page were wider than the screen and clipped the device line, the assignment tables and the repair buttons: a card kept the width of the widest table inside it. Cards now shrink to their container and tables scroll inside them; the repair buttons wrap. The selected entity on the map was hidden under its own panel on a phone; the map moves it into the free part when it is selected.

The field reports its first choice as well.

## v2.0.0, 2026-09-06

The production milestone (decision D97). Observability, System Health, backup and disaster recovery (phase 10), proven on the dev server; multi-path OpenCollar acquisition (phase 11): Web Bluetooth, raw log files and Cloudloop/Iridium, built from documentation and the local stack; data curation and corrections (phase 12); platform expansion (phase 13): The Things Stack, Actility, CRA IoT, EarthRanger direct, WildlifeNL, FerusTracker, Movebank exports, icons, dashboards and MCP write tools; production hardening (phase 14): security audit with application-level throttling, organizations as grouping, translation-ready frontend, release process, docs and dependency checks in CI. Then phase 15, correctness and usability from the first live days with KPN LoRa live in both directions: assignment dates from the data and the attribution repair, device health and last seen, per-channel traffic columns, gateway positions with their origin, the firmware-aware OpenCollar driver with golden tests, the metrics review, the entity page and device assignment, groups nested as deep as needed with the organizing page, the live map's layers panel with Entities, Features, Events and Coverage tabs, site-wide search, the technical details preference, the style pass and the coverage layer.

### Breaking

- KPN LoRa (ThingPark) data sources verify ThingPark's own push Token and need the tunnel interface authentication key as `as_key`; the bearer downlink mode is gone, so a source with `auth_mode` or `api_token` in its config must be edited to the one-key form before uplinks are accepted again.
- ChirpStack data sources talk to the server over gRPC only: `api_url` is `grpcs://host:443` or `grpc://host:8080`, the REST gateway path is gone, and a ChirpStack behind nginx needs the documented `grpc_pass` location for the API before downlinks, syncs and Test connection work again.
- Major version because 2.0 is the production milestone after fourteen unreleased phases of change since v0.6.0: new tables, six migrations, new pages, and the entity-first navigation; every migration downgrades (below).

### Configuration

- `RATE_LIMIT_ENABLED` (true), `RATE_LIMIT_AUTH_PER_MINUTE` (20), `RATE_LIMIT_INGEST_PER_MINUTE` (3000), `RATE_LIMIT_ACTIONS_PER_MINUTE` (60): application-level throttling; set the first to false only behind a proxy with its own limits.

It shows only where collars were.

- Metrics review (phase 15, decision D102): metrics that registered themselves on arrival appear under Needs attention, New metrics, with the devices reporting them, the last value and time; label, unit and category are set inline; the summary counts them and the Data Explorer marks them as not defined yet (`GET /attention/metrics`).
- Firmware-aware OpenCollar driver (phase 15, decision D100, ADR 0021): one layout per firmware range named after the firmware's reference decoder, chosen from the version the collar last reported (written on the device by its status message) or learned inside a raw log stream; the layout is the decoder version of every record; ports 8 and 17 decode into state records up to firmware 6.16, port 21 air quality into measurements from 7.2 (metric seeds, migration 0018), the status feature bit 2 is the RF scanner only before 7.1, and a port a layout lacks is a trace note that says which firmware sends it. The three reference decoders are vendored (MIT) and a golden file of their output for every recorded frame is checked against the driver.
- Gateway metadata kept whole (phase 15): every adapter normalises the coordinates a platform sends per receiving gateway into the reception's `location` (LORIOT and The Things Stack now too), the registry records where a gateway's position came from and when (`location_source`, `location_at`, migration 0017), and a position set by an administrator is kept over platform updates, which used to overwrite it with the next reception.

The project page is called Traffic, not LoRaWAN traffic.
- Device health and last seen (phase 15, decision D104): drivers declare the fields of a device's health with units and thresholds; the OpenCollar driver declares the status message's battery, charging, temperature, uptime, errors, reset reason, firmware and hardware and the last fix's quality. Device reads carry `last_seen_at` and `health`; the device page shows a Health card, the devices list shows last seen and a compact health line instead of the update time, the map's current-state features carry the health level, battery and last status.
- Assignment dates from the data and the attribution repair (phase 15, decision D103): the assignment dialogs offer the device's first data, the day it joined the project, now, or a date (the start of that day in the project's timezone); the device page shows how many records sit before the earliest project or entity assignment and offers to move the assignment start back, which attributes those records and recomputes the current state; creating an assignment or handing a device over attributes the records already inside the new range as well (`GET /devices/{id}/data-span`, `POST .../project-assignments/{id}/extend-start`, `POST /projects/{id}/entity-assignments/{id}/extend-start`). The case: SP051307's Bluetooth log, 29,253 measurements and 223 positions decoded correctly but without a project.
- Needs attention: select unknown identities (the header box takes every row of the search) and create devices for all of them at once, with one device type, an optional project and an optional entity type that gives every device an entity of the same name and assignment, or ignore the selection; names come from the platform's device name where the adapter stores it (KPN ThingPark) and else from the external id, taken names get the external id appended, and the result lists what was skipped and why (`POST /attention/identities/bulk-create-devices`, `bulk-ignore`; decision D96). The Unknown identities table shows the platform's name.
- KPN LoRa (ThingPark) ready for the live run (decision D95): ThingPark's own push Token (SHA-256 over the report's body elements, the URL query and the tunnel interface authentication key) is verified by the webhook when the `as_key` credential is stored, so the KPN portal needs no custom header; every downlink carries a 64-bit `CorrelationID` from the command id, which the `DevEUI_downlink_Sent` report echoes to move the command to transmitted; the best gateway's coordinates (`LrrLAT`, `LrrLON`) reach the gateway registry; Actility's and IoT Academy's published pushes with their keys are golden fixtures; the webhook reads the raw query string so the `+` of a time offset survives; the runbook has the Device Manager steps and KPN's downlink URL. The source form asks for one key and the AS ID only: the bearer downlink mode (`auth_mode`, `api_token`) is gone because ThingPark has no such scheme, and KPN's downlink URL is the default. Adapters may declare `verify_webhook` for platforms that sign their pushes. From the live run: a sent report with `DeliveryStatus` 0 fails the command with ThingPark's causes per slot translated (a sent one shows them as information), the uplink frequency reaches the traffic view, the downlink channel's status comes from the last command through the source instead of asking for a connection test ThingPark cannot answer, deep links no longer double the slash of a `web_url` entered with one, a port 0 uplink or an unknown port (the legacy Modem-E message on port 199 that KPN collars on old firmware send) is a note on the trace instead of a dead letter.

Found on the dev server, where three benchmark exports of 4.9 GB each had nothing to remove them.
- Production hardening (phase 14, decisions D91 to D94): application-level throttling of login, registration, password reset, token and webhook calls and AI actions (`RATE_LIMIT_*` settings, 429 with `Retry-After`), an access matrix test over every API operation and role, the curation permission checks moved into route dependencies, dependency audits (`pip-audit`, `npm audit`) and documentation checks (links, anchors, Mermaid fences, the MCP tool reference) in CI, a security page with the audit's findings; organizations as a grouping of projects for server admins (CRUD under `/admin/organizations`, `organization_id` on projects, a filter and column on the Projects page); a translation-ready frontend (i18next with the English catalogue, `t()` everywhere, a lint rule against hard-coded text, a language switch; English is the only language); the release process guide; the benchmark generator writes in time order with `--compress`.
- Events ChirpStack posts over its HTTP integration are recorded as received by webhook, so the source's HTTP channel counts them (they counted for the MQTT channel before).
- The documented nginx location for ChirpStack's gRPC API routes on the content type, so the web UI's grpc-web calls on the same `/api.` paths keep working (the first snippet locked the web UI out); checked against nginx 1.18.
- ChirpStack's gRPC client explains a proxy that answers a plain HTTP status (the `grpc_pass` location missing or not reloaded) as a connectivity problem with the fix, instead of "COMMAND_REJECTED ... http2 header with status"; troubleshooting entry with the curl check.
